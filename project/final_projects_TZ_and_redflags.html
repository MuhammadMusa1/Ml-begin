Готов — дать датасет и не мешать Жизнеспособен после 1 правки Требует смены жанра
Как пользоваться. Раздайте каждому ученику его карточку. Проект допускается к защите только когда закрыты все поля: выбран конкретный датасет (не «данные из интернета»), назван числовой/классовый таргет, метрика соответствует типу задачи, есть baseline (модель Dummy…) и обёрнутый sklearn Pipeline. Без baseline и Pipeline потолок оценки ≈ 14/20.

Перед защитой · Demo Day

Красные флаги

Пройдите по списку с каждым учеником накануне защиты. Хотя бы один незакрытый пункт роняет оценку.

Нет baseline

Не с чем сравнить модель — непонятно, «умная» она или просто угадала частый ответ.
Проверка: в коде есть DummyRegressor / DummyClassifier, и метрика модели лучше baseline.

Метрика не по типу задачи

MAE для классификации или Accuracy для регрессии — классическая путаница (см. карточку #2).
Проверка: регрессия → MAE/RMSE; классификация → Accuracy + F1. Одной Accuracy на несбалансированных классах мало.

Проверка на обучающих данных

Модель «отвечает» на то, что уже видела — метрика завышена и врёт.
Проверка: есть train_test_split(..., random_state=42), метрика считается на test.

Утечка данных (data leakage)

Признак содержит ответ (или таргет входит в фичи) — «MAE≈0», а на реальных данных провал. См. #1.
Проверка: ни один признак не вычисляется из таргета; будущая информация не попадает в прошлое.

Нет sklearn Pipeline

Ручной препроцессинг «протекает» с train на test — обязателен с урока 10.
Проверка: весь препроцессинг + модель внутри одного Pipeline; .fit() только на train.

Прогноз «в открытое будущее»

Задача незаметно становится временным рядом — рано для финального проекта. См. #5.
Проверка: таргет известен для каждой строки датасета; предсказываем «следующий шаг», а не абстрактное завтра.

Крошечный датасет (<100 строк)

Модель переобучается, метрики скачут от запуска к запуску. См. #8.
Проверка: ≥100–200 строк; если данные свои — собраны всем классом.

Хардкод чисел в презентации

Метрики вписаны руками, а не получены из реального прогона — на вопрос «покажи код» проект рушится.
Проверка: каждая цифра в слайдах воспроизводится запуском ноутбука при жюри.

Нет интерпретации результата

«Модель работает» — недостаточно. Нужно объяснить, где и почему ошибается.
Проверка: есть важность признаков / confusion matrix и 2–3 фразы «что это значит».

Нет README и живого демо

Родители реагируют на работающий Gradio, а не на слайды. Это сильнейший момент защиты.
Проверка: есть README (задача/данные/как запустить) и Gradio, с которым родитель сам может повзаимодействовать.
Финальный проект: 18–20 «Отлично» · 15–17 «Хорошо» · 12–14 «Зачёт» · <12 доработка. Без baseline и Pipeline потолок ≈ 14.
