Урок 15 · Свёрточные сети

Готовим данные для CNN — пошагово и без ошибок

Сама сеть — это 20% работы. Остальные 80% — правильно подготовить данные. Здесь мы пишем код шаг за шагом, и рядом с каждым правильным блоком показываем типичную ошибку: как её узнать и как починить.

📐 Форма (shape)Сколько картинок, какого размера, сколько цветовых каналов.
🔢 Диапазон значенийПиксели идут от 0 до 255. Сеть любит от 0 до 1.
🏷️ Метки (labels)Правильные ответы: числа 0–9. Их не нормализуем!

Три вещи выше держим в голове ВСЕГДА. 90% ошибок на этом уроке — это когда одну из них перепутали с другой.

1Загружаем готовый датасет картинок

Зачем: нам не нужно вручную открывать тысячи файлов. В Keras уже есть набор CIFAR-10 — 60 000 маленьких фото по 10 категориям (самолёт, кот, собака, корабль…). Что ждём: четыре переменные — картинки и ответы, отдельно для обучения и для проверки.

✓ ПИШЕМ ТАК
from tensorflow.keras.datasets import cifar10 # распаковываем сразу в 4 переменные: (картинки, ответы) для train и test (X_train, y_train), (X_test, y_test) = cifar10.load_data() print("Картинок для обучения:", len(X_train)) print("Картинок для проверки:", len(X_test))
✗ А ТАК НЕ НАДО
data = cifar10.load_data() # получили «матрёшку» из кортежей… X_train = data[0] # …и теперь X_train — это (картинки, ответы) вместе!
Почему ломается: load_data() возвращает вложенную структуру ((X_train, y_train), (X_test, y_test)). Если распаковать «наполовину», картинки и ответы слипнутся, и на обучении вылезет непонятная ошибка формы. Как чинить: распаковывай сразу в 4 переменные, ровно как в правильном блоке.

2Смотрим на форму — что вообще внутри

Зачем: прежде чем что-то делать с данными, надо понять их размер. Первое, что делает опытный человек — печатает .shape. Что ждём: (50000, 32, 32, 3).

✓ ПИШЕМ ТАК
print("Форма картинок:", X_train.shape) # (50000, 32, 32, 3) print("Форма ответов:", y_train.shape) # (50000, 1)
Читаем (50000, 32, 32, 3) по частям:
• 50000 — сколько картинок
• 32 — высота в пикселях
• 32 — ширина в пикселях
• 3 — три цветовых канала: красный, зелёный, синий (RGB)
Каждая картинка — это стопка из 3 табличек 32×32, где в каждой клетке число яркости.
✗ ЧАСТОЕ ЗАБЛУЖДЕНИЕ
«Картинка — это просто список из 3072 чисел». Нет! Для CNN важна именно объёмная форма (32, 32, 3) — сеть смотрит на соседние пиксели, ищет края и формы («лупа»). Если сплющить картинку в плоский список Flatten ДО свёрточных слоёв — сеть перестанет «видеть» соседей, и весь смысл CNN пропадёт. Сплющивать будем, но позже и внутри модели.

3Проверяем диапазон значений

Зачем: чтобы понять, нужна ли нормализация. Смотрим на минимум и максимум. Что ждём: от 0 до 255.

✓ ПИШЕМ ТАК
print("Минимум:", X_train.min(), " Максимум:", X_train.max()) # Минимум: 0 Максимум: 255 → значит, это яркость пикселей, надо нормализовать

4Нормализация — самый частый источник ошибок

Зачем: сеть учится стабильнее и быстрее, когда числа маленькие и в одном диапазоне [0; 1]. Делим все пиксели на 255. Что ждём: тот же .shape, но значения теперь от 0.0 до 1.0.

✓ ПИШЕМ ТАК
# ОБЯЗАТЕЛЬНО и train, и test — одинаково! X_train = X_train / 255.0 X_test = X_test / 255.0 print("Теперь максимум:", X_train.max()) # 1.0
✗ ОШИБКА A — нормализовали только train
X_train = X_train / 255.0 # про X_test забыли…
Почему ломается: модель училась на числах [0;1], а на проверке получает [0;255] — как будто выучил язык, а спрашивают на другом. Точность на тесте резко «проседает» без видимой причины. Правило: что сделал с train — то же сделай с test.
✗ ОШИБКА B — нормализовали ответы
y_train = y_train / 255.0 # НЕТ! это метки классов 0–9, а не пиксели
Почему ломается: y — это номера категорий (0 = самолёт, 3 = кот…). Делить их на 255 бессмысленно, модель не сможет обучиться. Нормализуем только картинки X, метки y не трогаем.
✗ ОШИБКА C — «делёж на месте» на целых числах
X_train /= 255 # массив целых → результат обрежется до нулей
Почему ломается: исходные пиксели — целые числа. Деление «на месте» без точки может обрезать всё до 0. Как чинить: пиши через новую переменную и с точкой — X_train = X_train / 255.0.

5Разбираемся с метками (labels)

Зачем: модель должна знать правильные ответы. У CIFAR-10 это числа 0–9 в форме (50000, 1). В нашем курсе мы держим их как целые числа и используем функцию потерь sparse_categorical_crossentropy — тогда one-hot кодирование НЕ нужно.

✓ ПИШЕМ ТАК (наш стандарт курса)
# метки оставляем как есть — целые числа 0..9 print("Пример ответов:", y_train[:5].ravel()) # [6 9 9 4 1] # в модели используем loss="sparse_categorical_crossentropy"
✗ ЛИШНЯЯ РАБОТА
from tensorflow.keras.utils import to_categorical y_train = to_categorical(y_train) # one-hot… а loss всё ещё sparse — конфликт!
Почему путаница: есть два способа — либо метки-числа + sparse_categorical_crossentropy, либо one-hot + categorical_crossentropy. Их нельзя смешивать. Мы всегда выбираем первый: проще, меньше кода, меньше ошибок.

6Проверяем глазами — а точно ли это картинки?

Зачем: лучший способ убедиться, что данные живые — нарисовать одну картинку. Что ждём: увидим маленькое цветное фото.

✓ ПИШЕМ ТАК
import matplotlib.pyplot as plt plt.imshow(X_train[0]) # первая картинка (значения уже 0..1 — imshow это понимает) plt.title(f"Класс: {y_train[0][0]}") plt.axis("off") plt.show()
Мини-правило хорошего дата-сайентиста: «Не доверяй форме — посмотри на данные». Один imshow экономит час отладки.

★Готовый шаблон — скопируй и запусти с нуля

📋 Эта ячейка самодостаточна: запускается в свежем Colab без предыдущих ячеек.
# ===== ПОДГОТОВКА ДАННЫХ ДЛЯ CNN — ПОЛНЫЙ ШАБЛОН ===== import matplotlib.pyplot as plt from tensorflow.keras.datasets import cifar10 from tensorflow.keras import layers, models # 1. Загрузка (X_train, y_train), (X_test, y_test) = cifar10.load_data() # 2. Смотрим форму print("Форма:", X_train.shape, "| диапазон:", X_train.min(), X_train.max()) # 3. Нормализация — только картинки, и train, и test X_train = X_train / 255.0 X_test = X_test / 255.0 # 4. Проверяем глазами plt.imshow(X_train[0]); plt.axis("off"); plt.show() # 5. Модель ждёт РОВНО такую форму, как у одной картинки: (32, 32, 3) model = models.Sequential([ layers.Input(shape=(32, 32, 3)), # ← совпадает с X_train.shape[1:] layers.Conv2D(32, 3, activation="relu"), layers.MaxPooling2D(), layers.Flatten(), # сплющиваем ТОЛЬКО здесь, после свёрток layers.Dense(64, activation="relu"), layers.Dense(10, activation="softmax") # 10 классов ]) # 6. Метки — целые числа → sparse (наш стандарт курса) model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"]) model.fit(X_train, y_train, epochs=1, validation_data=(X_test, y_test))

✅ Проверь себя (5 вопросов)

  1. Что означает каждое число в форме (50000, 32, 32, 3)? Расшифруй все четыре.
  2. Почему картинки делим на 255.0, а метки y — нет?
  3. Друг нормализовал только X_train, а X_test забыл. Что случится с точностью на проверке и почему?
  4. Почему Flatten нельзя ставить в самом начале, до свёрточных слоёв?
  5. Мы держим метки как числа 0–9. Какую функцию потерь тогда нужно указать в compile?
Показать ответы (для преподавателя)
  1. 50000 — число картинок; 32 — высота; 32 — ширина; 3 — цветовые каналы RGB.
  2. X — это яркости пикселей 0–255, их приводим к [0;1] для устойчивого обучения. y — это номера классов, деление их на 255 разрушает смысл меток.
  3. Точность на тесте резко упадёт: модель училась на [0;1], а проверяется на [0;255] — разные «языки» данных.
  4. CNN ищет закономерности среди соседних пикселей (края, формы). Flatten в начале уничтожает эту 2D-структуру, и свёртки теряют смысл. Сплющиваем только после свёрток.
  5. sparse_categorical_crossentropy — работает с целочисленными метками без one-hot.
